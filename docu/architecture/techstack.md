decisions are binding; **proposed** entries are recommendations from the open ADRs and move to the
accepted tables when J accepts them. Everything else is open and listed in
[open-decisions.md](../adr/open-decisions.md). Versions are fixed in the build files when the backend

## Accepted

### Architecture

Decided in [ADR-0001](../adr/0001-architecture-concept.md) on 2026-10-25.

| Topic | Decision | Open decision |
|-------|----------|---------------|
| Backend structure | Layered everywhere: `api → service → repository`; DDD per module only by ADR | TD-32 |
| Service cut | One backend with one module per bounded context, one database; modules call each other through a public interface | TD-21 |
| Architecture checks | Automatic architecture tests for layers and module boundaries in the test command | TD-32 |
| Frontend architecture | Feature modules with a query cache, no global store | TD-30 |
| API versioning | No version in the path, compatible changes only; path version when external clients appear | TD-20 |

### Backend

Decided in [ADR-0002](../adr/0002-backend-stack.md) on 2026-10-25. Exact versions are pinned in
`pyproject.toml` and `uv.lock` when the backend is created.

| Area | Decision | Open decision |
|------|----------|---------------|
| Language and framework | Python 3.14 + FastAPI (Pydantic) | TD-05 |
| Packages and build | uv with lockfile | TD-05 |
| Database | PostgreSQL | TD-04 |
| Persistence access | SQLAlchemy 2 (async) + psycopg, migrations with Alembic | TD-04 |
| API description | OpenAPI generated by FastAPI (code-first); frontend types generated from it; Markdown API documentation only as functional complement | TD-19 |
| Formatter, linting, types | Ruff (lint, format) + ty | TD-01 (backend part) |

### Frontend

Decided in [ADR-0003](../adr/0003-frontend-stack.md) on 2026-10-25. Exact versions are pinned in
`package.json` and the lockfile when the frontend is created.

| Area | Decision | Open decision |
|------|----------|---------------|
| Approach and framework | SPA with React + TypeScript (strict) in `frontend/` | TD-22 |
| Build and tooling | Vite, npm, ESLint, Prettier | TD-24, TD-01 (frontend part) |
| UI components and styling | Tailwind CSS + shadcn/ui, icons `lucide-react` | TD-25 |
| Design | Own design tokens following the shadcn scheme with roles (primary, secondary, …), light and dark; design concept in [design-concept.md](design-concept.md), dark mode as default | TD-31 |

### Interview Sets

Decided in [ADR-0006](../adr/0006-local-semantic-matching.md) by J on 2026-11-02 for
[TWA-8](../product_backlog/backlog.md#epic-twa-8--interview-preparation), without the planned
measurement (postponed).

| Area | Decision | Open decision |
|------|----------|---------------|
| Matching approach | Names and aliases of the tools exact, plus embeddings with a small local model for the tools an ad only describes | TD-37 |
| Embedding runtime | ONNX Runtime with `tokenizers` inside the backend, no model server | TD-38 |
| Embedding model | paraphrase-multilingual-MiniLM-L12-v2, int8 ONNX (118.5 MB); downloaded once, outside the repository, mounted into the backend | TD-39 |
| Vector store | pgvector in the existing PostgreSQL (`pgvector/pgvector:pg16`) | TD-36 |
| Persisted similarity | One value per tool and set | TD-40 |
| Test database (measurement only) | Testcontainers with the pgvector image; not installed while the measurement is postponed | TD-03 |
